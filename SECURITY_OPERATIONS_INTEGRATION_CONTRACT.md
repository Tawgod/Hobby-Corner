## Administration consumer contract — HC-ADMIN mock v0.1.0
Security-approved for isolated synthetic UI consumption only, pending Manager ownership agreement. Logical adapter methods, not HTTP URLs or real canonical permission IDs. No network calls, production imports, cookies/tokens, real records, real grant evaluation or DB. All test IDs/names opaque and fictional; backend-derived capability/visibility and effective-access results are supplied mock data, never inferred from role names. UI may filter/sort/display supplied fields, validate form shape, display explicit denied/unknown, and simulate preview/confirm responses through in-memory fixtures; no client permission computation. No actual credential collection including PIN, TOTP, passkey, recovery code, API key or session token. Authentication/step-up/enrollment ceremonies are Security-owned; UI displays required state and future handoff intent only.

All methods return an envelope {contractVersion:"0.1.0",status:"ok"|"denied"|"authentication_required"|"step_up_required"|"stale"|"approval_required"|"unsupported"|"unavailable"|"invalid",requestId,policyVersion?,data?}; safe display message optional. Non-ok data absent except explicitly safe state metadata such as a required-action label. Unknown version/state/missing capability fail closed; no raw errors, hidden record existence, sensitive credentials, permission-source leakage. Opaque IDs, explicit tenant/environment/location/resource/field references; no implicit future locations/wildcards. Cursor paging with stable opaque cursor, limits and search parameters; only backend-admitted records and fields. Version is not authorization. Do not invent final IDs or role names; mock labels marked synthetic/provisional.

| Logical method | Request and safe response intent |
|---|---|
| getAdminContext | No client actor claims. Supplied identity label, environment, current policy version, allowed navigation/actions, assurance state; no secrets. |
| searchEmployees / getEmployee | Query/cursor/limit or opaque employeeId; display name, active status and permitted store/location references; Timeclock owns canonical employee records. No PIN or private employee record. |
| listRoles / getRole / listOperations | Search/cursor/filters; role ID/label/status/revision; operation ID/label/domain/description/provisional status/scope schema/prerequisites/approval requirements and consumers, backend-supplied. Never turn unresolved alias into grant. |
| getAssignments | Employee ID; current permitted role memberships, individual grants/restrictions, scopes, expiry/status, revision. |
| explainAccess | Exact employee, operation and typed scope; independently authorized explanation supplied by backend, allowed/denied/unknown and safe source references. Permission explanation not execution approval; ordinary business responses never contain sources. |
| listDevices / listSessions / listServices | Authorized subject and cursor; safe labels, masked identifiers, status, last activity/expiry and permitted actions. No raw device credentials/session IDs usable as tokens, or key material. |
| listAudit / listApprovals | Authorized filters/cursor; safe event/approval IDs, operation, actor label, result, time, correlation, permitted target/revision and status; never raw payload or secret. |
| previewChange | Typed draft action and target, current expected revision/policy version, explicit complete scope, reason and expiry if applicable. Backend-derived impact summary (gained/lost scopes, affected employees, conflicts/prerequisites, approval/assurance), opaque preview ID, expiry and allowed confirmation state. |
| confirmChange | Opaque preview ID, expected revision and idempotency key; separate explicit confirmation. In mock only, returns pending approval, denied/stale/step-up, or synthetic committed result; readback via authorized get/list. Never auto-retry unknown outcome. No actual mutations or optimistic success. |
| getChangeStatus | Opaque request/change ID; safe current pending/committed/denied/unknown status only if authorized. No repeat execution. |

Exact JSON schema/OpenAPI, HTTP method/path, status taxonomy, CSRF, authentication transport, request/response field definitions, approval binding and production policy owned by Security; future files docs/security/admin-api/v1/**. v0.1.0 is logical mock profile only; no endpoint exists by virtue of this document.
