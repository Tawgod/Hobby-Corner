## Initial count proposal — deliberately bounded
Closed-store Jan6 count, one outlet/session. Capture immutable per-employee/device scan events (unique event ID, exact string identifier, quantity default 1, server received UTC and optional scan UTC, source), import batch records (hash, original file metadata, row index, source and employee). CSV or Excel import preview: preserve exact text and leading zeros; reject ambiguous numeric coercion/Excel lost zeros rather than invent codes. Repeated intentional scans accumulate; identical file reimport is rejected or identified before commit; normalized semantic duplicate warnings, explicit reviewed replacement/correction, no blind dedupe of intentional repeated lines. Resolve exact SKU/UPC/supplier code to actual canonical Lightspeed product/variant/outlet; collision or unmatched never auto-select. Show canonical stock and cost if available, aggregate by ID not typed code. Example 001234 x3 plus imported quantity 5 =8, duplicate import remains 8. Recount/correction references original events, append audit not overwrite. Review uncounted list explicitly, signed qty/cost variance with valuation source if verified, count totals and reconciliation manifest. Freeze scans for final approval; snapshot current provider stock, require approved policy for zero/unseen/damaged and late movements; one controlled absolute final count/import or supported API method, verified in test tenant first, stable per-product operation receipts, stop uncertain effects and read back before retry. No direct database stock edits. Initial migration must not load RMS on-hand. Count timestamps retained, but advanced automatic movement history reconstruction, restock, location management, recurring counts and general ledger deferred P1/P2. If sales/receipts occur during closure, isolate and explicitly reconcile before final application; no assumption of a complete movement feed. Export a recovery manifest and verify final stock independently; after trading begins never blindly restore old stock.
