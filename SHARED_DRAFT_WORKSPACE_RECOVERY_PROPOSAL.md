## Ownership
Core owns reusable draft persistence, lifecycle, optimistic snapshot concurrency, idempotency, transport-independent interfaces and recovery orchestration. Domain owners own schemas, content validation, allowed fields, revision acquisition/conflict handling, editing UI and final submission. Security exclusively owns identity, draft/read/field authorization, restrictions, session recovery, data protection policy and authorization contract. Manager allocates branches, exact pins and integration gates. Operations only owns separately assigned admin UI, not policy or backend. No extra permanent workstream proposed.

## Proposed logical contract HC-DRAFT/0.1 (names not accepted API)
create, list, saveSnapshot, restore, rename, discard, expire/purge, markSubmitted; separate operations with independent authorization, not actual registry IDs or HTTP routes. Trusted server actor/tenant/environment/tool ownership; opaque draft ID; domain schema/version, named project title (bounded/redacted), base record identifiers and revision evidence, validated unfinished intent payload, snapshot revision, idempotency key, timestamps, expiry policy revision, status. Server controls owner, timestamps, retention and revision. No access credentials, session tokens, approval proof or executable job in payload. No shared cross-employee visibility by default; sharing/transfer separately reviewed. List metadata and titles independently projected. Save expected snapshot revision plus idempotency key; same key/same canonical input returns acknowledged version, changed input conflicts. Atomic save/readback acknowledgement, out-of-order response guard, no last-writer-wins across tabs/devices. Retention expiry and save race handled atomically. Domain payload version migration explicit, fail closed unknown schema. No business mutations, remote dispatch, stock/payment changes, approval or business outbox on draft lifecycle. Draft audit separately scoped, no raw payload in logs. Final submit separate existing business transaction path with current exact permission, current record revision and applicable approval; changed intent requires new approval. Mark submitted only after verified business outcome; unknown outcome cannot trigger another submission. Preserve original command linkage without storing reusable authorization. No silent overwrite or automatic submission.

## Session behavior
Periodic snapshots while authenticated and authorized; manual Save Draft, dirty/saving/saved/unsaved/conflict/locked/expired status with last acknowledged server time. Proposed configurable debounce and interval, e.g. idle 3 seconds and dirty checkpoint 30 seconds, subject to UX/load review; bounded batching and backoff, no claim browser close handler guarantees writes. On lock/expiry hide sensitive data, stop writes, never extend session for save or permit anonymous post-expiry writes. Restore after reauthentication and independent current draft/read/field authorization plus restrictions. Acknowledge possible loss since last durable snapshot; do not promise post-expiry rescue. No unprotected localStorage/IndexedDB or shared workstation cache; in-memory unsaved content treatment requires Security review (clear/hide, no recoverable secrets). Protect transport and at-rest data per Security; deny if required protection unavailable. No real data in fixtures.

## Revision and retention
Distinguish draft snapshot revision from domain record revisions. On restore and before final submit fetch current authorized domain records, identify changed/deleted/unavailable targets and revoked fields, prevent unauthorized disclosure. Domain presents per-field/record conflict choices (discard proposed change, rebase/review, explicit permissible edit); never silently overwrite. Base values only where domain and Security approve minimization. Configurable server-owned retention, count/size quotas, expiry, deletion and audit; propose 14 days since last acknowledged edit with 30-day hard lifetime for initial review only, not owner-approved defaults. Reads do not extend retention; explicit authorized save may extend within cap. Expired drafts inaccessible even before cleanup; purge payload and review backups/audit retention; no resurrection. Manager/Security/owner must approve defaults, bounds, retention policy changes and purge behavior before production. No new settings activation.
